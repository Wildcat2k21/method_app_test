## 1. Описание метода и стратегии тестирования

### 1.1. Выбор методологии

| Тип            | Особенности тестирования                                                                                  | Применимость                                                |
| -------------- | --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| Веб-приложение | браузеры, сеть, сервер, адаптивная вёрстка                                                                | нет: игра не работает в браузере (сборка WASM не настроена) |
| Мобильное      | сенсорный ввод, ориентация экрана, батарея, прерывания                                                    | нет                                                         |
| **Десктоп**    | окно и оконная система, клавиатура и мышь, файловая система и права, драйверы графики, установка и запуск | **да**                                                      |

Змейка - **десктоп-приложение**: нативное окно (winit), рендер через Vulkan (wgpu), ввод с клавиатуры
и мыши, рекорд в локальном файле. Выбрана методология тестирования десктоп-приложений.

### 1.2. Что проверяется у десктоп-приложения

| Область                   | Риск для игры                                                                | Как проверяется        |
| ------------------------- | ---------------------------------------------------------------------------- | ---------------------- |
| Окно                      | поле обрезано или не помещается, окно растягивается и картинка искажается    | авто: `window.rs`      |
| Раскладка                 | клетка поля залезает под полосу HUD или за край окна                         | авто: `window.rs`      |
| Файловая система          | рекорд теряется между запусками, файл повреждён, папка недоступна для записи | авто: `persistence.rs` |
| Ввод                      | залипание клавиши при потере фокуса, кнопки мышью                            | ручной протокол DT     |
| Оконная система / графика | разные backends (Wayland, X11), драйверы                                     | ручной протокол DT     |
| Ресурсы (assets)          | запуск не из папки пакета → шрифт не найден                                  | ручной протокол DT     |
| Жизненный цикл            | закрытие окна, кнопка «Выход», сворачивание                                  | ручной протокол DT     |

### 1.3. Стратегия

1. Всё, что не требует настоящего окна, автоматизируется. Параметры окна строит функция `view::primary_window`:
   `main` передаёт её результат в `WindowPlugin`, а тест проверяет его напрямую.
2. Сохранение рекорда проверяется **двумя запусками** приложения с одним файлом во временной папке.
   Отдельная папка на тест: тесты идут параллельно и не мешают друг другу.
3. Поведение настоящего окна проверяется по ручному протоколу (раздел 3.2) с фиксацией окружения.

### 1.4. Запуск

```bash
cargo test --test lb6
scripts/test.sh lb6 --report
cargo run                          # ручной протокол
```
